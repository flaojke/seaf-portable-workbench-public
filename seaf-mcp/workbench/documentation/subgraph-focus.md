# Фокус на подграфе

Feature: **16**. Capability: `subgraph-focus`.

Откройте [рабочее пространство SEAF](/entities/docs/blank?dh-doc-id=local.lsv.workbench) или [отдельную вкладку](http://localhost:8091). Выберите нужный проект; ниже пример для ShopFlow.

Граф показывает окрестность компонента и помогает разобраться в зависимостях без просмотра всей системы. Это представление модели, а не её изменение.

## Как пользоваться

1. Откройте **Граф**.
2. В поле **Компонент** выберите ID из подсказок.
3. Задайте **Глубину** и **Направление**: все, исходящие или входящие связи.
4. Нажмите **Построить**.
5. Нажмите на другой узел или выберите его клавишей Tab и Enter: он станет новым центром. Для всей модели очистите поле компонента и снова нажмите **Построить**.
6. Наведите указатель на узел, чтобы увидеть полный ID, зону и классификацию данных.

## Пример ShopFlow

Укажите `demo.shop.delivery`, глубину **1**, направление **Исходящие**. В текущей модели у Delivery Service есть связи:

- `demo.shop.orders` — данные подтверждённого заказа / REST;
- `demo.shop.delivery_db` — заявки, inbox и outbox / SQL;
- `demo.shop.events` — ShipmentCreated / AMQP.

Переключите направление на **Входящие**: увидите связь Event Broker → Delivery с OrderConfirmed. При глубине **2** и **Все связи** добавятся соседи заказов и брокера. Возвращайтесь к исходному фокусу, уменьшая глубину.

## Как читать граф

Центральный узел выделен. Стрелка показывает ссылку source → target из components.links; название связи выводится на небольших графах. Межзонные связи выделяются другим цветом, если у обоих компонентов заполнены разные trustZone.

Данные относятся к текущей загруженной модели project imports. Для проверки исходников откройте объект по ID в **Объекты** либо попросите MCP прочитать сущность.

## Ограничения

UI предлагает глубину 0–6, сервер ограничивает обход восемью шагами. Рисунок показывает первые 80 узлов с предупреждением о сокращении. При глубине 0 остаётся только выбранный компонент.

Это граф components.links: документы, contexts и все возможные типы SEAF-зависимостей в него автоматически не включаются. В блоке **Данные компонентов и связей** можно раскрыть таблицы и источники, переданные сервером. Отсутствующий target обозначается unresolved, а не выдуманным компонентом; исправлять такие ссылки следует в исходной модели и проверять runtime validation.
