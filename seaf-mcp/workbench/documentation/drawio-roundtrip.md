# Draw.io: импорт, экспорт и редактор

> Переносимый профиль: В переносимой поставке draw.io обслуживается локальным Node-сервисом. Docker не требуется. Поддерживаются клиентское редактирование и XML; облачные интеграции, серверный PDF-export и MathJax в offline-профиль не включены. См. [инструкцию Windows](/entities/docs/blank?dh-doc-id=local.lsv.portable).

Feature: **drawio**. Capability: `drawio-roundtrip`.

Откройте [рабочее пространство SEAF](/entities/docs/blank?dh-doc-id=local.lsv.workbench) или [страницу рабочего пространства](/entities/docs/blank?dh-doc-id=local.lsv.workbench). Выберите нужный проект; ниже пример для ShopFlow.

В разделе **draw.io** можно открыть XML-диаграмму, распознать вершины и связи в модель, экспортировать components и редактировать исходный diagram artifact в локальном редакторе.

## Импорт компонентов

1. Нажмите **Файл с компьютера** либо укажите путь и **Открыть из проекта**.
2. Выберите страницу; если не выбрана, обрабатывается первая.
3. Выберите режим **Объединить с моделью** либо **Заменить распознанный набор**.
4. Нажмите **Распознать компоненты**.
5. Изучите semantic diff, файлы и неизвестные endpoints. Затем проверьте и примените черновик.

Вершины превращаются в components, рёбра — в links. Cylinder/database-подобные фигуры распознаются как database, остальные — преимущественно component; это эвристика XML-стилей, а не OCR/LLM. Метаданные seafId сохраняют ID. Без них создаётся стабильный ID вида imported.n_<hash> по странице и cell ID.

Режим replace заменяет свойства каждого распознанного существующего объекта; он не удаляет все отсутствующие на рисунке объекты проекта. В merge сохраняются существующие связи, которых нет на частичной схеме, и дополнительные свойства сопоставленных links. Неоднозначные параллельные связи требуют ручного согласования. Для старого XML без SEAF-метаданных сохраняются недекларированные свойства существующего объекта; у новых объектов нужно проверить назначенные по умолчанию тип и владельца.

## Экспорт модели

Нажмите **Экспорт модели**: скачивается architecture.drawio с компонентами текущей модели и существующими links между известными компонентами. Экспорт включает seafId, title, entity/kind, owner, description и seafProperties: произвольные свойства компонентов и связей, в том числе protocol, encrypted и dataClassification. Это экспорт всего components, а не выбранного в другом разделе подграфа.

## Редактирование существующего файла

1. Для готового примера ShopFlow введите `diagrams/shopflow-delivery.drawio` и нажмите **Открыть из проекта**.
2. Нажмите **Открыть редактор**. Используется локальный host `http://localhost:8092`; схема не передаётся внешнему diagrams.net.
3. Передвиньте фигуры/измените подписи и выберите **File → Save** в самом draw.io; доступно также Ctrl+S при фокусе внутри редактора. Сохранение редактора передаёт актуальный XML в проверяемый черновик.
4. Изменённый XML попадёт в черновик по указанному исходному пути.
5. Нажмите **Проверить в SEAF**, затем **Сохранить в Git и обновить SEAF**.

Сохранение диаграммы не синхронизирует архитектурные компоненты автоматически. Для этого отдельно выбирают **Распознать компоненты** и проверяют модельный diff.

Кнопка **Подготовить сохранение файла** работает с загруженным XML и недоступна, пока открыт canvas-редактор. Изменения на холсте сохраняйте через File → Save: это исключает подготовку старой версии XML вместо текущего расположения фигур.

## Пример ShopFlow

В комплект примера включена схема `diagrams/shopflow-delivery.drawio`. Выберите проект **ShopFlow**, откройте **draw.io**, вставьте этот путь в **Файл в проекте** и нажмите **Открыть из проекта**, затем **Открыть редактор**. Найдите **Delivery Service**, **Order Service**, **Event Broker** и **Delivery DB**. Передвиньте Delivery Service и нажмите File → Save. В черновике останется тот же путь, а diff покажет геометрию XML. После проверки и применения результат сохранится в Git; определения components остаются прежними до явной синхронизации модели.

Для нового файла можно сначала нажать **Экспорт модели**, изменить расположение в редакторе и указать другой путь, например `diagrams/shopflow.drawio`. Экспорт не заменяет готовый файл, пока вы явно не подготовите и не примените его сохранение.

При повторном импорте seafId сопоставляет `demo.shop.delivery` с существующим компонентом. Метаданные сохраняют пользовательские свойства и аннотации потоков. Для первого знакомства используйте merge и изучите diff: режим replace намеренно заменяет распознанный объект целиком.

## Ограничения

Поддерживаются mxfile/mxGraphModel, обычные и compressed страницы. Интерфейс ограничивает выбираемый файл 450 КБ, чтобы укладываться в лимит проверяемого текстового artifact. Сам XML-parser имеет дополнительные верхние границы: вход 4 МиБ, распакованные страницы 16 МиБ, 64 страницы и 20000 mxCell. DTD/ENTITY запрещены; сообщения редактора проверяются по origin и iframe source.

Распознавание не определяет бизнес-смысл фигуры и не отличает всякий декоративный vertex от компонента. Неподдерживаемые non-vertex элементы и рёбра с неизвестными концами перечисляются в warnings и структурированном `unmapped`, остаются в исходном XML и не превращаются в выдуманные компоненты или links. Служебные root/layer клетки и явно обозначенные группирующие контейнеры исключены из такого списка.

Read-only диаграммы можно читать и скачивать. Подготовка сохранения и импорт в модель отключены; File → Save из iframe сообщает об ограничении и не записывает исходный файл. Для нового компонента выбирайте пространство имён с существующим родителем и подходящий контекст: например `demo.shop.tracking` для ShopFlow. Ошибки родителя или контекста выявляются валидаторами до Git-коммита.

Если draw.io не подтвердил готовность, примерно через 15 секунд появляется инструкция запустить редактор и проверить диагностику. Загруженный XML и его скачивание сохраняются. Сообщения save от чужого origin или другого окна игнорируются.

Для отображения файла как отдельного документа меню нужен docs-объект; простое сохранение XML его автоматически не добавляет.
