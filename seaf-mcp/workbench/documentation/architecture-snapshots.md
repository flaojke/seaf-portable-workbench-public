# Снимки архитектуры

> Переносимый профиль: В переносимом профиле снимок поддерживает Git и обычные папки. Вместо imageId native runtime содержит identity с хэшами runtime-файлов; воспроизведение требует их совпадения. Для папки head — локальная ревизия. Пункты про Docker-образ ниже относятся к Docker-профилю. См. [инструкцию Windows](/entities/docs/blank?dh-doc-id=local.lsv.portable).

Feature: **25**. Capability: `architecture-snapshots`.

Откройте [рабочее пространство SEAF](/entities/docs/blank?dh-doc-id=local.lsv.workbench) или [страницу рабочего пространства](/entities/docs/blank?dh-doc-id=local.lsv.workbench). Выберите нужный проект; ниже пример для ShopFlow.

Снимок сохраняет поддерживаемые архитектурные исходники workspace, локальные импорты, OpenSpec и сведения о runtime. Проверка SHA-256 помогает обнаружить изменение сохранённых файлов.

## Как пользоваться

1. Убедитесь, что Git-проект чистый и образ SEAF доступен.
2. Откройте **Снимки**, введите название и нажмите **Создать снимок**.
3. Изучите выданные id, head и runtime.imageId.
4. В списке нажмите **Проверить**. Результат содержит ok, число файлов и failures.
5. Нажмите **Скачать ZIP** и сохраните архив вместе с информацией об используемом образе.
6. Нажмите **Preview**, чтобы открыть сохранённые исходники в отдельном портале на runtime-образе снимка. Основной проект не перезаписывается.

## Пример ShopFlow

Название: **ShopFlow перед изменением доставки**. Снимок фиксирует текущий commit модели, файлы `microservices-demo`, доступные текстовые архитектурные артефакты общего workspace и OpenSpec. После создания нажмите **Проверить**: для неповреждённого архива ожидаются `ok: true` и пустой failures.

При изменении одного исходника следующий снимок получает другую идентичность содержимого. Повторная фиксация одинакового набора файлов, runtime и настроек использует тот же id; title и время не входят в расчёт идентичности.

## Содержимое

В ZIP есть `workspace/`, `openspec/` и `manifest.json`. Manifest содержит пути и SHA-256 файлов, project, head, runtime imageId/repoDigests, root manifest, параметры запуска и версию Node сервиса workbench. Версия Node самого портала однозначно фиксируется содержимым Docker-образа. Включаются поддерживаемые текстовые расширения, а не произвольные бинарные файлы.

Многогигабайтный Docker-образ **не включён**. Для воспроизведения нужен отдельно доступный образ с указанным imageId. Снимок не загружает удалённые импорты автоматически; они должны быть материализованы в локальном workspace.

## Ограничения

**Проверить** проверяет целостность сохранённых файлов и ZIP; это не запуск восстановленного портала и не доказательство доступности runtime. **Preview** дополнительно создаёт отдельный портал из сохранённого workspace, manifest и environment и требует наличия точного imageId. Это безопасный способ посмотреть восстановленное состояние; он не перезаписывает live.

Загрузка произвольного ZIP в новый сервер и кнопка «восстановить live» пока отсутствуют. Просмотр через Preview использует снимки, которые уже сохранены на этом сервере. Runtime validation выполняется отдельно; доступность страницы не заменяет проверку всех правил.

Общий workspace может содержать источники нескольких проектов; состав смотрите в manifest. Содержимое YAML/JSON копируется как есть: снимок не является сервисом автоматического удаления секретов.
