# Проекты: папки Windows и Git

Раздел **Проекты** доступен в левом меню SEAF и в рабочем пространстве. Карточка показывает источник, провайдера GitLab/GitHub/GitVerse/Git, путь, манифест, право записи и тип истории. Активный проект выделен.

## Подключить существующую папку

1. Нажмите **Выбрать папку…** или введите полный путь Windows.
2. Выберите автоматическое определение типа, локальную папку или существующий Git-клон.
3. Нажмите **Проверить папку**, проверьте `root.yaml` или выберите другой корневой манифест. При импортах за пределами выбранного корня нужен общий workspace с локальными зависимостями.
4. Задайте название и право редактирования, затем нажмите **Подключить**.
5. **Выбрать** загружает модель в рабочее пространство. **Открыть** запускает и открывает портал именно этого проекта.

Папка без Git остаётся обычной папкой: `.git` не создаётся. Если папка лежит внутри чужого Git-корня, она не становится его самостоятельным Git-проектом автоматически.

## Git по URL

Введите HTTPS/SSH URL и новую или пустую папку назначения, затем **Клонировать и подключить**. Допустимы GitLab, GitHub, GitVerse и другие Git-серверы. Авторизация использует настройки пользователя; токены не вставляйте в URL. Если корневой манифест отличается от `root.yaml`, укажите его в форме подключения. Сохранение архитектуры создаёт локальный коммит; push — отдельное явно запрошенное действие.

## Сохранение, версии и удаление

- **Сохранить ZIP** скачивает поддерживаемые архитектурные файлы и manifest экспорта. Git metadata, бинарные assets и внешние импорты не входят в этот экспорт. Полную папку проекта можно копировать после остановки.
- Правки объектов сохраняются в **Редакторе** после diff и проверки. ZIP не заменяет эту операцию.
- **Новая версия** фиксирует именованное локальное состояние; для Git создаёт ветку `codex/<имя>` на текущем коммите без checkout и push.
- **Клонировать** создаёт независимую локальную копию и подключает её. Git metadata, `.env`, node_modules и служебные каталоги не копируются.
- **Отключить** убирает регистрацию, сохраняя файлы и локальную историю.
- **Удалить…** требует ввести ID проекта и перемещает writable папку в локальную корзину. Read-only источники не удаляются. Это действие отличается от отключения; хранение корзины и истории занимает место.

## Пример

Подключите отдельную копию ShopFlow как локальную папку, откройте `demo.shop.delivery` в редакторе, измените владельца и сохраните после проверки. Затем откройте **Сравнение → Обновить историю версий**, выберите две ревизии и сравните изменения. Для дополнительной копии нажмите **Проекты → Клонировать** и задайте новую папку.

## Ограничения

Локальная история хранится в data/state и переносится вместе с комплектом. Внешнее изменение файлов после подготовки черновика блокирует его применение. Сохранение Git-проекта требует чистой рабочей копии; чужие правки нужно предварительно согласовать и сохранить самостоятельно. Ошибка reload не отменяет сохранённую версию: повторите обновление в карточке результата. Удаление между разными дисками может быть отклонено без удаления файлов; используйте отключение и управляйте папкой в Проводнике.
