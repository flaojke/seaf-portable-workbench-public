# SEAF MCP

## Переносимый профиль — 2.2.0

Основной новый режим: Windows 10/11 x64, собственный Node.js и Git, локальные
PlantUML/draw.io, работа без Docker. Поставка запускается Start.cmd, подробности
в [portable/README.md](../portable/README.md). Реестр и история находятся в data,
а source Git содержит только исходники, шаблоны и закреплённые build inputs.

Источники `git` и `directory` используют одну цепочку proposal → diff → validate
→ apply → reload. Git-проект получает локальный коммит, обычная папка — локальную
ревизию без создания .git. Поля `revision.kind/id/fingerprint` универсальны;
`commit` сохраняется для совместимости Git. Ошибка reload не повторяет сохранение.

Раздел **Проекты** подключает папки, Git HTTPS/SSH и готовые клоны, сохраняет ZIP,
создаёт версии и копии. Отключение сохраняет файлы; удаление требует явного
подтверждения и перемещает writable папку в корзину. **Редактор** поддерживает
формы, enum/справочники и component.links. Подключённые read-only источники
не получают запись через вложенные/родительские подключения.

Новые MCP-методы: `inspect_project`, `connect_project`, `clone_project`,
`get_project_revision`, `list_revisions`, `select_active_project`,
`update_project_connection`, `disconnect_project`, `delete_project`, `copy_project`,
`create_project_version`, `push_project`. Последние destructive/network write
действия требуют соответствующего явного запроса пользователя; apply никогда
не делает push автоматически. Полные схемы возвращает tools/list.

Пути Windows выбираются через Projects или задаются в локальном реестре.
Архитектурные пути в YAML остаются относительными и используют `/`. Native
validation/preview работают на копии workspace с loopback-процессами; snapshots
фиксируют binary identity. Docker-профиль сохранён для прежних регистраций.

Генерация MCP-конфигурации для перенесённого комплекта:

```powershell
runtime\node\node.exe portable\mcp-config.mjs
```

Она создаёт data/mcp.config.json для текущего пути. Используйте wrapper
portable/mcp.mjs: он добавляет bundled Git/SSH и runtime URLs в окружение.
После обновления клиента переподключите MCP, чтобы получить новую схему.
Если tools не отображаются в уже открытой сессии, сервер остаётся зарегистрирован;
клиенту может потребоваться переподключение или перезапуск. Для публикации этой
поставки использовался тот же stdio-сервер через локальный MCP SDK-клиент.

Последующие разделы с . и Docker описывают исходный локальный профиль
и его историческую приёмку 2.0.1. Для portable выбирайте runtime `native` и
собственный data/projects.json, а не копируйте персональную конфигурацию машины.

## Проверка устойчивости — 2.0.1

Поставка 05.11.2026 закрывает оставшиеся сценарии OpenSpec: ошибки хранилища,
перенос черновиков, read-only, недоступность зависимостей, очистку preview,
повтор reload после сохранённого коммита и полный draw.io save lifecycle.
Фактическая матрица и копии отчётов находятся в истории изменения OpenSpec.

Из корня `.` полный набор без пропусков:

```powershell
$env:SEAF_E2E = '1'
$env:SEAF_BACKEND_E2E = '1'
node --test --test-concurrency=1 seaf-mcp/test/*.test.mjs seaf-mcp/workbench/test/*.test.mjs
node seaf-mcp/workbench/test/browser-gates.mjs
node seaf-mcp/workbench/test/drawio-gates.mjs
node seaf-mcp/workbench/test/launcher-gates.mjs
```

Браузерные проверки используют установленный Chrome и Playwright из локального
runtime. Записывающие тесты создают отдельные Git-проекты и порталы; исходная
ShopFlow остаётся неизменной. Тест ярлыка использует частную ошибочную точку
готовности, а рабочий портал сохраняет доступность.

Если Git-коммит сохранён, но reload не удался, в интерфейсе нажмите
**Повторить обновление SEAF**. Для MCP `reload_project` принимает необязательный
`proposal_id`: повтор обновляет журнал предложения и не создаёт коммит.
После обновления сервера переподключите MCP-клиент, чтобы обновить список
аргументов инструментов. Старый вызов с одним `project` также поддерживается.

## Рабочее пространство v2

В SEAF: **Документы → Доработки LSV → 03. Рабочее пространство**.
Отдельно: <http://localhost:8091/>. Ярлык SEAF запускает портал, draw.io
и Node-сервис рабочего пространства. Проекты берутся из `projects.json`;
новому writable-проекту нужны собственный Git, manifest, validation workspace,
образ SEAF и URL портала. Справочные репозитории остаются read-only.

Команды из `./seaf-mcp` (Node 22.12+):

```powershell
node workbench/server.mjs
node --test test/*.test.mjs workbench/test/*.test.mjs
$env:SEAF_E2E = '1'
node --test workbench/test/e2e.test.mjs
```

В этом компьютере Node доступен также в установленном Codex runtime;
`seaf-docker/launcher.ps1` находит его автоматически. Порты 8080/8091/8092
привязаны к loopback. Это локальный инструмент одного пользователя;
публикация в корпоративную сеть требует отдельной аутентификации и TLS.

Новые MCP-инструменты: `propose_objects`, `list_drafts`, `propose_draft`,
`semantic_diff`, `create_snapshot`, `verify_snapshot`, `create_preview`,
`focus_graph`, `grounded_context`, `verify_evidence`, `find_contradictions`,
`import_drawio`, `export_drawio`, `diagnose_project`. Обычный цикл записи
сохранён: `propose_draft → get_proposal → validate_change → apply_change`.
Черновик, снимок или preview сами не создают коммит рабочей модели.

HTTP API `GET /api/session`, `POST /api/action` используется интерфейсом;
для POST нужны JSON, session `X-SEAF-CSRF` и допустимый Origin. Токен
живёт до перезапуска сервиса. Endpoint не принимает команды shell или
произвольные корни проектов. Состояние: `state/workbench/`; draft содержит
baseHead и fingerprint всего validation workspace. Снимки включают
поддерживаемые архитектурные исходники, OpenSpec и точный runtime imageId;
Docker-образ хранится отдельно. Preview использует отдельный read-only bind
и порт, срок 30 минут сохраняется в preview-records и восстанавливается
после перезапуска. Остановка доступна в интерфейсе.

Браузер кэширует интерфейс service worker и хранит модель/черновики в
IndexedDB. После первого успешного открытия можно редактировать локально;
runtime validation, Git и reload выполняются после восстановления связи.
Экспорт JSON позволяет перенести draft; несовпадающие project/format/base
отклоняются. Очистка данных браузера удаляет его локальные черновики.

AI-ответы в интерфейсе — извлечение фактов с проверяемыми источниками,
без самостоятельного вызова платной модели. Внешняя LLM получает
`grounded_context`: claims, project/file/line, commit, SHA-256 и excerpt.
`verify_evidence` проверяет свежесть. Поиск противоречий читает исходные
YAML до слияния и явные документные утверждения; выводы требуют review.

draw.io работает в локальном контейнере 8092, digest закреплён в compose.
XML импортируется в черновик, исходный diagram сохраняется отдельным
проверяемым изменением. Компоненты и XML синхронизируются только явным
действием. Существующие ID/layout/styles и другие страницы сохраняются.

Разработка: `../openspec/config.yaml`, master `specs`, change
`add-architecture-workbench`, delta specs, tasks и acceptance.
Каждая функция документирована с примером в меню LSV

Локальный MCP-сервер для внешнего агента. Транспорт stdio; сервер запускает сам
MCP-клиент. Отдельный постоянно работающий процесс или HTTP-порт не нужен.
Модель и учётная запись выбираются в клиенте агента. Ключ LLM серверу не нужен.

## Подключение

Сервер `seaf` уже зарегистрирован в Codex через `codex mcp add`.
Если инструменты не появились в текущем чате, перезапустите клиент.
Для других MCP-клиентов пример настроек находится в `mcp.config.json`.
Путь к Node должен быть доступен клиенту; в регистрации Codex используется
абсолютный путь установленного runtime. После обновления runtime его можно
перерегистрировать: `codex mcp add seaf -- node ./seaf-mcp/server.mjs`.
Для больших проектов рекомендуется установить tool timeout клиента 120 секунд.

Примеры запросов агенту:

- «Через MCP seaf найди участников оформления заказа в проекте shopflow.
  Приведи ID компонентов и файлы-источники».
- «Покажи входящие и исходящие связи demo.shop.orders».
- «Добавь Delivery Service в shopflow: владелец Logistics, назначение — доставка
  оплаченных заказов. Подготовь diff, проверь модель, затем сохрани и обнови SEAF».

## Инструменты и порядок изменения

`list_projects`, `list_artifacts`, `read_artifact`, `search_artifacts`,
`get_entity`, `get_dependencies`, `query_model` читают зарегистрированные проекты.
Поиск возвращает файл и строку, сущность — исходный YAML.
JSONata выполняется в отдельном worker с лимитом 2 секунды; доступны стандартные
функции JSONata, без пользовательских функций SEAF. Это представление импортов
проекта, а не всего собранного манифеста портала с системной метамоделью.

`propose_entity` создаёт/заменяет сущность в YAML с сохранением комментариев.
`propose_change` принимает набор `{path, content}`; `content: null` удаляет файл.
Для нового файла агент должен включить изменение imports в тот же набор.
Для изменения отдельных полей сначала прочитайте сущность: propose_entity
заменяет её целиком. Данные proposal и diff сохраняются в `state/<uuid>`.

`validate_change` проверяет YAML/JSON и дерево импортов, создаёт копию workspace
и запускает настоящий SEAF в отдельном Docker-контейнере без сети и портов.
Все архитектурные проверки должны пройти. Это строгий gate, без baseline старых
нарушений. Образ и корневой manifest задаются для каждого проекта.

`apply_change` принимает только проверенное предложение. Проверяются HEAD,
содержимое проекта и импортируемого workspace. Нужен чистый Git-проект.
Запись защищена межпроцессным lock; при ошибке до коммита восстанавливаются
изменяемые файлы. Создаётся локальный commit от `SEAF MCP <seaf-mcp@localhost>`;
push не выполняется. Повторное применение возвращает прежний commit.
При сбое перезагрузки commit остаётся сохранённым, возвращается статус
`committed_reload_failed`; используйте `reload_project`, а не повторную запись.
Это не атомарная транзакция файловой системы при аварийном отключении Windows:
в состоянии `applying` сохранены исходные файлы для восстановления.
После аварии проверьте Git/diff и журнал предложения перед удалением
`.git/seaf-mcp.lock`.

## Другие проекты

Добавьте запись в `projects.json` (пути считаются от этого файла):

```json
{
  "id": "another-project",
  "title": "Другой проект",
  "root": "../path/to/workspace/model",
  "manifest": "root.yaml",
  "writable": true,
  "validation": {
    "workspace": "../path/to/workspace",
    "manifest": "workspace/root.yaml",
    "image": "seaf-local:2026.33.0-performance"
  },
  "portal": "http://localhost:8080"
}
```

Каждый writable-проект должен иметь собственный Git-репозиторий. Workspace
содержит модель и локальные общие импорты. Используйте соответствующий проекту
образ SEAF с нужными плагинами/метамоделью и проверенным начальным состоянием.
Remote GitLab/Bitbucket imports для автономной проверки нужно предварительно
материализовать в локальный workspace: контейнер проверки намеренно без сети.
Запись за пределами корня проекта запрещена; общие слои меняются через отдельный
зарегистрированный проект. `writable:false` позволяет читать справочные репо
без доступа к записи; для файлового поиска `manifest` не обязателен.

Если reload защищён секретом, задайте `reloadSecretEnv` — имя переменной среды
с секретом. Сам секрет передайте серверу из окружения MCP-клиента.
Портал с OIDC требует отдельной настройки машинной авторизации; текущий адаптер
реализует локальный портал и reload-secret. Ролевые права не переносятся из
портала автоматически: этот stdio-сервис работает с правами локального
пользователя и явным реестром проектов. Для общего многопользовательского
сервера потребуется отдельная авторизация.

## Установка и тестирование

Node 22+ и Git должны быть доступны процессу MCP. Docker Desktop нужен для
проверки и работы локального SEAF. Зависимости зафиксированы package-lock.json:
`npm ci --ignore-scripts`.

```powershell
node --test ./seaf-mcp/test/bridge.test.mjs
$env:SEAF_E2E='1'
node --test ./seaf-mcp/test/bridge.test.mjs
```

E2E создаёт временный Git-проект внутри state, проверяет отказ неверного
компонента, применение корректного, идемпотентность и отклонение устаревшего
предложения. Рабочие компоненты ShopFlow при этом не меняются.
`demo-result.json` подтверждает реальную запись страницы «Работа через MCP»
в ShopFlow, Git-коммит и успешную перезагрузку портала.
