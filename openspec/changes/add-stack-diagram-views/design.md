# Design
Stable node identity is project/section/id. Components and contexts drive the context and passport. The passport includes declared service app_components placement references. Technology filters use technologies catalog status, never component status. Missing facts remain explicit.
Native placement follows checked SEAF core schemas: ta/services/base_entity.yaml app_components and stand; ta/services/cluster.yaml network_connection and availabilityzone. The earlier invented stackDeployments adapter was removed. Unmapped infrastructure is not inferred.
The deterministic local parser accepts limited Russian/English service declarations and data transfer statements plus component/link DSL. Unsupported descriptions fail; no remote provider is called. Preview shows operations and diff. Staging verifies initial, build and latest model bases before saving a normal draft. Applying still requires normal diff/propose/validate/explicit apply. UI captures project and text version and ignores detached panels.
Model fingerprints use canonical semantic JSON for all revisions including drafts. Comparison preserves baseline positions. Parallel links use endpoints and occurrence index. Historical context/passport selectors must exist in both sides.
Static HTML/SVG plus browser PNG are exported in ZIP with inventory, legend, UTC date, revision and content hashes. No third-party code or assets copied. Publication and full portal validation remain separate, explicitly unperformed steps.
