## Why

Пользователю нужна переносимая поставка SEAF для Windows и подключение как Git-проектов, так и обычных каталогов Windows. Сейчас основной портал и проверки зависят от Docker, Workbench требует Git даже для просмотра, а исходники ядра не входят в корневой Git. Простое копирование launcher не решает эти ограничения.

## What Changes

- Подключение конкретной папки Windows через системный диалог или ввод пути, с предварительным определением манифеста и возможностей проекта.
- Разделение источника проекта, истории изменений и runtime проверки/preview. Существующие Git-проекты сохраняют proposal → diff → validate → commit → reload.
- Переносимая ZIP-поставка для Windows 10/11 x64 с собственным Node.js, Git runtime, offline схемами/draw.io, ShopFlow и небольшими примерами; установка Node/Git/Docker на целевой машине не требуется.
- Воспроизводимая сборка из будущего корневого Git: исходники, закреплённые зависимости и сценарии сборки отдельно от бинарной поставки, секретов и пользовательских данных.
- Инструкция, пример и ограничения в разделе «Доработки LSV»; публикация через MCP proposal lifecycle.

## Capabilities

### New Capabilities

- `project-connections`: подключение каталогов Windows и явное определение типа источника.
- `portable-windows-distribution`: переносимая поставка и повторяемая сборка.
- `local-project-history`: локальные ревизии, diff и проверки при изменении обычной папки без Git.
- `repository-authoring-guide`: структурированная документация по исходникам, требованиям к проектам и созданию схем/L2 с проверенным примером.

### Modified Capabilities

Оформлены дельты: `connection-diagnostics`, `object-editing`, `offline-drafts`, `architecture-snapshots`, `branch-preview`, `semantic-diff`, `grounded-answers`, `drawio-roundtrip`. Дополнительные задачи пользователя включают самостоятельные разделы «Проекты», «Редактор» и структурированный справочник по требованиям к подключаемой архитектурной кодовой базе.

## Impact

Затрагиваются Engine, Workbench/API, MCP-схемы, конфигурация проектов, запуск core и упаковка. Архив предыдущей поставки не изменяется. Git push не выполняется автоматически. Скачанные read-only проекты сохраняют ограничения записи. Принятые ответы: `clarifications.md`. Реализация и приёмка отмечаются только по наблюдаемым проверкам.
