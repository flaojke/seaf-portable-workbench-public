# Interactive architecture editing from the diagram workspace

The current composer edits a visual definition and opens an object passport separately. Users need to select an object or interaction on the canvas, edit its real properties and component composition, and create, change or delete integrations and information flows without leaving the workspace.

Provide a canvas-first workspace with a contextual inspector, pan/zoom/fit and an explicit queue of semantic edits. Combine that queue with diagram geometry and documents in the existing reviewed draft lifecycle. Keep the live 2.2 installation available until the tested 2.3 distribution is ready. Publish only the resulting SEAF source to the already authorized private repository after final acceptance.

Use existing object-editing/schema adapters, retain unedited properties and expose supported hierarchy/endpoint mappings explicitly. DocHub composition follows dotted component identifiers. Creating/editing/deleting direct children is included; renaming or dragging an existing subtree to another parent is excluded because it requires a separate reference migration.

Documentation with a ShopFlow example, exact source behavior and limits must appear under Доработки LSV Architecture/documentation publication uses the registered MCP lifecycle. All mutation acceptance uses disposable projects.
