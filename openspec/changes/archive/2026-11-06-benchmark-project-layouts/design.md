## Методика

Сравниваются семь логически одинаковых моделей. Baseline содержит два больших typed-файла; v1/v2 выделяют только системы с головным systems.yaml/прямыми root imports; v3/v4 выделяют системы и исходящие интеграции по папкам с прямыми root imports/общими typed-агрегаторами; v5 добавляет root.yaml каждой системы; v6 упаковывает 20 систем в доменную группу с её manifest.

Размеры: 1000/3000 систем, 3000/9000 интеграций и столько же links. Все ID, определения, упорядоченные links и контексты совпадают; импортируемые sections сравниваются canonical SHA-256 через настоящий Engine.model и через native runtime API. Парные layouts имеют byte-identical typed payload. Корневой manifest — depth 0; глубина папки и глубина imports считаются отдельно.

Измерения проводятся последовательно без параллельных build/test-нагрузок. Новый процесс Node используется для каждого cold-process sample; кеш ОС не сбрасывается и не называется cold disk. Порядок layouts ротируется и разворачивается между повторениями. Warm reload повторяет реальный /core/storage/reload. Fs/YAML probes устанавливаются только внутри временного worker и не меняют файлы продукта.

Browser использует реальный Chrome: новая context для first UI, reload с сохранённым HTTP cache для warm UI, PlantUML-представление контекста 50 систем. Все 50 подписей проверяются в реальном SVG. Готовность реестра требует видимой строки объекта, а не только #app; полной отрисовкой всех строк эта метрика не называется. Deny-only proxy блокирует внешнюю сеть, сохраняя HTTP cache; ошибки и таймауты записываются, а не превращаются в PASS.

Первоначальный SmartAnts smoke100/focus50 завершился ошибкой маршрутизации. Это отрицательное наблюдение сохранено отдельно. В основной сравнительной серии выбран PlantUML, успешные времена не приписываются SmartAnts. Перед сериями исправлен локальный renderer CORS preflight для RqUID; все измерения выполнялись на одной версии исправления.

HTTP-профиль обслуживает те же YAML-файлы через собственный loopback server с указанной искусственной задержкой на запрос. Он моделирует цену запросов; не выдаётся за реальный GitLab/API/корпоративный сервер.

Локальная серия: 42 process samples (7 × 2 размера × 3 повтора), по два unchanged-source reload и три browser phases. HTTP: 21 sample на 1000 систем с 10 мс на запрос, без browser series. Raw source: 14 cases × 5 запросов после startup, весь defining YAML проверяется byte-exact. Лимит 500000 UTF-16 символов относится к MCP/Workbench, не к raw API ядра.

V6 проверяет фиксированные пакеты последовательных ID по 20; реальные бизнес-домены и ownership как фактор производительности не моделируются. Отдельный V8 CPU profile одного baseline3000 reload используется только для анализа горячих функций, а не в сравнительных timing-медианах. Один профиль не доказывает причинность всей нелинейности и не является RPS-тестом.

В отчёте указываются runtime/node/core identity, ОС/CPU/память без hostname/серийных номеров, число повторов, медиана/разброс и ограничения малой выборки. Source transport и warm/cold scope не смешиваются. Числовое ранжирование появляется только после наблюдаемых успешных прогонов. Рекомендация объединяет измерение, ответственность команд, review и сохранение стабильных ID/интеграций.
