## Context

См. proposal.md: Why. Есть локальный SEAF на Windows/Docker и stdio MCP с реестром проектов. YAML и Git — источник истины. MCP сохраняет proposal на диске, проверяет модель в изолированном контейнере, проверяет базовый commit/fingerprint, применяет с локальным Git commit и затем вызывает reload. Полная метамодель портала отличается от объединённых project imports MCP; стандартный JSONata query_model не заменяет runtime validation.

## Goals / Non-Goals

Цель — единая работа с зарегистрированными проектами без обхода проверок. Интерфейс одинаково обслуживает ShopFlow и другие проекты. Продукт должен явно различать локальный draft, проверенный proposal, сохранённый commit и обновлённый портал.

В этой поставке не требуется автоматический Git push, совместное редактирование несколькими пользователями или запуск/обучение собственной LLM. Контракт доказательных ответов доступен внешнему агенту; наличие RAG не является доказательством конкретного утверждения. Внешний draw.io host может требовать сеть; работа со скачанным черновиком модели от него не зависит.

## Decisions

### 1. Общий API поверх существующего проверяемого write lifecycle

Интерфейс обращается к локальному service adapter с той же моделью проектов и proposal, которую использует MCP. Для точечных и пакетных правок формируется одно предложение, которое получает diff и validation. Прямое редактирование файла из браузера исключается архитектурой. Альтернатива отдельного writer в UI усложнила бы блокировки, контроль устаревания и восстановление.

Local API слушает loopback, проверяет Origin/CSRF для запросов из браузера и не передаёт секреты в интерфейс. Read-only и доступ к файловым путям проверяются сервером. Проект берётся из реестра; пути ограничены корнем проекта. Удаления показывают входящие ссылки и результаты проверки. Частичная ошибка пакета не даёт скрытого частичного commit.

### 2. Черновики и снимки имеют разные назначения

Черновик — редактируемый локальный набор операций с project ID, base commit/fingerprint, версией формата и временем сохранения. Он сохраняется в browser storage и переносимом JSON-файле. Изменения не публикуются при восстановлении. При появлении связи сервер сравнивает базу перед созданием proposal; конфликт требует явного обновления/переноса правок.

Снимок — манифест и содержимое исходников, включая импортируемые локальные слои: project ID, Git commit, digest каждого файла, root manifest, точный imageId/repoDigests runtime и объявленные параметры запуска. В архив не включаются Docker image bytes и окружение процесса с credentials; поддерживаемые исходные файлы копируются как есть, без обещания редактировать секреты в YAML/JSON. Сериализация и порядок файлов стабильны. Remote imports требуется предварительно материализовать локально. Preview снимка проверяет состав/хэши и использует сохранённые workspace, manifest/environment и отдельно доступный imageId. Альтернатива сохранения только commit недостаточна для внешних импортов и runtime.

### 3. Один индекс сущностей для edit, diff, graph и ссылок

Индекс строится из зарегистрированных project imports и сохраняет provenance: project, artifact, entity type, ID. Generic editor работает с любым верхнеуровневым разделом и объектным ID, поддерживает форму свойств и JSON/YAML-представление. Метамодель помогает форме, но не ограничивает новые типы объектов; окончательная проверка остаётся SEAF runtime.

Semantic diff сравнивает каноническую модель по type/ID и путям свойств; массивы сохраняют значимый порядок. Перестановка YAML ключей/отступов не создаёт смысловой правки. Изменение ID по умолчанию показывается delete+add; rename — только с явным сопоставлением. Context/sequence документы не переписываются эвристически: diff показывает запрошенные правки и предупреждает о неактуальных явных ссылках.

### 4. Граф и потоковые аннотации — представления модели

Subgraph вычисляется ограниченным обходом по направлению/глубине. Результат содержит список узлов, рёбер, исключённых/неразрешённых ссылок и provenance. Фильтр не удаляет данные.

Зоны доверия и классы данных задаются расширениями модели. Поток содержит source, target, protocol, data classification и границы. Неизвестная зона не считается безопасной. Явное нарушение подходящей trustPolicies и unresolved endpoint блокируют общий Engine.validate preflight; это не только визуальное предупреждение. Неизвестные значения остаются unknown, а не доказательством защищённости или автоматическим нарушением произвольной политики.

### 5. Preview изолирован от live

Git ref разрешается в commit, создаётся отдельный каталог и runtime/порт. Для preview фиксируются ref/commit, ошибки, URL и срок жизни 30 минут. Записи expiry сохраняются на диске и перечитываются при Workbench.init. Межпроцессный start lock и SEAF_PREVIEW_LIMIT (по умолчанию 3) ограничивают параллельные старты. Процесс не переключает HEAD рабочего проекта и не меняет live compose. Остановка удаляет выбранный контейнер и его expiry record; временный workspace может сохраняться для диагностики. Альтернатива checkout текущего workspace разрушила бы изоляцию и открытые proposals.

### 6. AI возвращает проверяемые evidence records

Источник содержит фактические project/artifact, entity ID, диапазон строк/excerpt, content SHA-256 и repository HEAD. Hash обозначает рабочие байты, commitRole=repository-context не выдаётся за доказательство committed bytes. Ответ связывает claims с собственными source records; verify_evidence проверяет hash, excerpt и commit. Незарегистрированный workspace import без независимого Git HEAD остаётся unverifiable и не попадает в verified claims. Отсутствующие факты обозначаются явно.

Contradiction review сравнивает структурированные поля и доказуемые расхождения документов, возвращает обе стороны и уровень уверенности. Лексическая похожесть без несовместимых утверждений не считается доказанным противоречием. Результат — отчёт; запись исправлений требует отдельного обычного proposal. Текст источников не меняет инструкции агенту.

### 7. Draw.io с сохранением идентичности

Разбор поддерживает обычный mxGraphModel и mxfile, в том числе сжатые страницы. Parser ограничивает размер/сложность, не загружает внешние сущности. Вершины распознаются как кандидаты компонентов, рёбра — связи; пользователь видит mapping и неизвестные shape/endpoint перед импортом. Метаданные SEAF type/ID обеспечивают повторный импорт без дублей. Геометрия хранится в diagram artifact и не выдаётся за архитектурное свойство.

Экспорт строит корректный mxfile всего components выбранного проекта с ID/названиями/связями и безопасными JSON metadata для поддерживаемых произвольных свойств компонентов и links. Trust annotations, nested custom data и explicit false сохраняются; визуальные ID/названия имеют приоритет над metadata, а небезопасные/непредставимые JSON значения отвергаются. Merge частичной legacy-схемы сохраняет посторонние links и их policy metadata, неоднозначные совпадения отвергаются. Встроенный локальный редактор проверяет origin и source iframe. Сохранение исходного drawio artifact формирует отдельный proposal; синхронизация модели явная. Версии сторонних зависимостей зафиксированы.

### 8. Документация и SDD входят в поставку

Каждая функция получает документ в меню **Доработки LSV**, с входом в интерфейсе, шагами, примером ShopFlow, ограничениями и ссылкой на соответствующую capability. Единый workshop ведёт через draft → diff → validate → commit → reload. SDD-документ объясняет master/delta lifecycle и команды локального OpenSpec CLI.

Acceptance.md связывает сценарии и фактические доказательства. Tasks отмечаются только после проверки; структурный OpenSpec validate не подтверждает продуктовые сценарии. 2026-11-04 root принял реализацию 11 capabilities и выполнил sync 36 ADDED requirements в masters с сохранением baseline. Change остаётся active для явно открытых QA; дельты помечены already synced. Sync не подменяет archive и не превращает непроверенный UI error path в PASS.

## Risks / Trade-offs

- [Локальное хранилище браузера очищено] → экспортируемый draft и явный индикатор сохранения.
- [Удалённые импорты меняются] → digest/commit и отказ заявлять полную воспроизводимость при неполном снимке.
- [Generic editor допускает неверное свойство] → предварительный diff, schema/runtime validation, исправление до commit.
- [Слишком большой граф/diagram] → ограничения глубины, числа элементов и размера с понятной ошибкой без зависания.
- [Draw.io внешний host недоступен] → локальный XML сохраняется, экспорт/повторное открытие доступны; сетевое ограничение показано.
- [AI выводит неподтверждённую связь] → обязательный source record, проверка hash и различение факта/предположения.
- [Preview расходует ресурсы] → ограничение количества, явная остановка и очистка только своих ресурсов.

## Migration Plan

1. Зафиксировать baseline specs и контракты; не мигрировать upstream проекты в writable.
2. Добавить API и UI с новыми versioned форматами, сохраняя старые MCP tools и YAML.
3. Опубликовать документацию в разделе LSV и пройти acceptance на ShopFlow и временном втором проекте.
4. Проверить чистый запуск, read-only, stale proposal, ошибку validation, ошибку reload и восстановление.
5. После приёмки синхронизировать deltas в masters и архивировать change. Откат runtime — предыдущий образ/код; откат модели — отдельный Git revert через проверяемую процедуру. Черновики/снимки не удалять автоматически при откате.
