# SEAF-Portable

**Форк SEAF.ArchTool** для переносимой работы с архитектурой на Windows, с универсальным редактором, Git и локальными проектами, MCP и автономными схемами.

Оригинальный проект SEAF.ArchTool: [seafteam/seaf-archtool-core на GitVerse](https://gitverse.ru/seafteam/seaf-archtool-core). Git URL оригинала: `https://gitverse.ru/seafteam/seaf-archtool-core.git`.

Это производная разработка, а не официальный релиз команды SEAF. Ядро версии **2026.33.0** сохранено в `vendor/seaf-archtool-core`; исходная точка, локальные коммиты и изменения описаны в [UPSTREAM.md](UPSTREAM.md) и `vendor/seaf-archtool-core/UPSTREAM.json`.


## Что добавляет форк

- Переносимый ZIP для **Windows 10/11 x64** с собственными Node.js, Git, Java, PlantUML и draw.io; установка ПО и Docker для локальной работы не требуются.
- Раздел **Проекты**: выбор активного проекта, папки Windows, HTTPS/SSH Git и готовые клоны, версии, копирование, ZIP, отключение и подтверждённое удаление в корзину.
- Раздел **Редактор**: системы и другие объекты, справочники/enum, информационные потоки и интеграции, точечные и пакетные изменения.
- **Интерактивный конструктор схем**: выбор узлов и связей, масштаб и перемещение полотна, свойства реальных объектов, состав компонентов, интеграции и потоки данных с единым проверенным сохранением.
- Контролируемая запись: **diff → проверка → Git-коммит или локальная ревизия → обновление SEAF**. Без автоматического push и перезаписи устаревших предложений.
- Внешние агенты через **MCP**: поиск архитектуры, ответы с источниками, предложения и проверки изменений. Сервис сам не вызывает внешнюю LLM.
- Локальные черновики, семантическое сравнение, снимки, preview, фокус на подграфе, потоки данных и зоны доверия, draw.io roundtrip.
- Примеры **ShopFlow** и **Hello**, включая C4 L2, владельцев из справочника и enum статусов.
- OpenSpec и инструкции в меню **«Доработки LSV»**, включая **«Документация SEAF»**.

## Интерактивная работа в 2.3.0

Версия **2.3.0** расширяет конструктор интерактивным инспектором компонентов, состава, интеграций и потоков. Проверены окончательный ZIP, перенос в другую папку, включённые frontend/backend и MCP. Поставка 2.3.0 заменяет 2.2.0. [Состав, результаты и ограничения 2.3.0](docs/release-2.3.0.md).

Требования ведутся в OpenSpec; принятые изменения архивированы без повторной синхронизации masters: [enhance-diagram-workspace](openspec/changes/archive/2026-11-10-enhance-diagram-workspace/acceptance.md) для интерактивного редактора и [improve-seaf-usability](openspec/changes/archive/2026-11-10-improve-seaf-usability/acceptance.md) для десяти включённых улучшений интерфейса:

1. Общий поиск по архитектуре и действиям через Ctrl+K.
2. Реестры больших моделей с фильтрами, сортировкой, колонками и сохранёнными представлениями.
3. Понятные результаты проверки с переходом к объекту и полю для исправления.
4. Паспорт объекта: назначение, владелец, связи, документы и происхождение.
5. Видимый контекст проекта, источника, версии, доступа и этапа сохранения.
6. Восстановление незавершённой формы, автоматический локальный черновик, отмена и повтор правок.
7. Мастер создания системы со связанными объектами и единым diff.
8. Избранное, недавние объекты и ссылки на конкретное представление.
9. Пошаговый просмотр взаимодействий в сценарии.
10. Читаемые поля, подсказки, обязательные свойства и управление с клавиатуры.

**Конструктор схем** поддерживает сетевой, прикладной и компонентный уровни. Определение схемы, её представление и явно выбранные изменения модели сохраняются в файлах подключённого проекта через цикл diff, проверки и сохранения. Инструкции, пример и ограничения находятся в меню **«Доработки LSV → 22. Интерактивный редактор схем»**.

## Запуск готового комплекта

1. Полностью распакуйте ZIP в доступную для записи папку.
2. Запустите **Start.cmd** и дождитесь открытия браузера.
3. Выберите проект в меню **Проекты**, правки выполняйте в **Редакторе**.
4. Перед переносом или завершением запустите **Stop.cmd**.

Для переноса настроек и истории копируйте остановленный комплект вместе с `data`. Внешние папки проектов переносятся отдельно. Адреса сервисов выбираются на свободных loopback-портах; сведения находятся в `data/run.json`. Внешние Git и AI требуют сети и авторизации пользователя.

[Полная инструкция: запуск, перенос, MCP и ограничения](portable/README.md).

## Исходники и сборка

| Каталог | Назначение |
|---|---|
| `vendor/seaf-archtool-core` | Отслеживаемые исходники ядра с LICENSE, NOTICE и provenance |
| `seaf-mcp` | MCP/API, Workbench, Git и локальная история |
| `portable` | Сборщик, закреплённые inputs, launcher и offline-сервисы |
| `examples` | Чистые архитектурные примеры ShopFlow и Hello |
| `openspec` | Master/delta specifications, задачи и фактическая приёмка |

На Windows x64 с Node.js >=22.12:

```powershell
node portable/build.mjs --output dist/SEAF-Windows-x64
```

Первое получение закреплённых зависимостей требует интернета. Готовая поставка работает локально offline. Сборка использует tracked sources и lockfiles; игнорируемые `repositories` и `seaf-docker/workspace` не являются её входными данными.

`dist`, runtime-бинарники, node_modules, data, кеши и персональные конфигурации исключены из Git. ZIP поставки публикуется отдельным релизным артефактом. [Разработка](CONTRIBUTING.md), [MCP и проверки](seaf-mcp/README.md).

## Альтернативный Docker-профиль

`seaf-docker/compose.yaml` и `launcher.ps1` сохраняют прежний локальный запуск. Он использует отдельно подготовленные образы/модели и не требуется для переносимой сборки.
