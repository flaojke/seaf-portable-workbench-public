# Требования к подключаемому проекту

| Что | Требование и пример |
|---|---|
| Корень | Читаемая папка Windows с выбранным YAML-манифестом, например `root.yaml`. Файл может называться иначе. |
| Структура | Имена подпапок произвольны. Удобно разделить `architecture/`, `docs/`, `diagrams/`; это соглашение, а не требование ядра. |
| Манифест | Корень YAML — mapping. Секции `components`, `contexts`, `docs` и другие подключаются напрямую или через `imports`. |
| Импорты | Указывать реальные файлы относительно импортирующего YAML: `architecture/components.yaml`. Файл должен быть доступен; повторные/циклические импорты MCP-редактор отклоняет. |
| Workspace | Все локальные зависимости для проверки должны находиться внутри выбранного workspace. Если импорт выходит в соседний проект, подключите общий workspace с его локальной копией. |
| Пути | В модели использовать `/`, а не `D:\...`. Путь Windows задаётся в форме подключения. Offline-модель не загружает HTTP/Git-импорты и внешние PlantUML include. |
| Идентификаторы | Использовать стабильные ID, например `demo.sales.orders`; русские названия — в `title`. Рекомендуются латиница, цифры, `_` и точки; точные pattern зависят от типа сущности. |
| Запись | Writable-доступ, валидный манифест и runtime проверки. Read-only источники можно изучать без разрешения записи. |

Минимальный корень:

```yaml
imports:
  - architecture.yaml
  - docs.yaml
```

## Git и обычная папка

**Git:** собственный корень клона, существующий HEAD и чистое рабочее дерево для применения. Ссылки HTTPS/SSH клонируются в новую/пустую папку; используются credentials/ключи пользователя, без токена в URL. Вложенная папка чужого Git не считается самостоятельным Git-проектом автоматически.

**Обычная папка:** `.git` не нужен и не создаётся. История хранится отдельно в data/state. Любая внешняя правка после подготовки предложения делает его устаревшим. При переносе внешней папки переподключите путь; встроенные примеры используют относительные регистрации.

## Ограничения нашего MCP-редактора

Поддерживаемые изменяемые артефакты: `.yaml`, `.yml`, `.md`, `.json`, `.mmd`, `.puml`, `.plantuml`, `.drawio`, `.xml`. Запрещены обходы `..`, абсолютные пути в операциях, скрытые компоненты пути и symlink/junction-выходы. Бинарные изображения могут использоваться документами, но не редактируются этим текстовым API и не входят в «Сохранить ZIP» архитектурных файлов. Предложение объединяет до 50 файлов, каждый текстовый файл — до 500 000 символов. `.env`, `.git` и node_modules не являются архитектурными данными для редактора.

Preview, снимки и текстовый экспорт MCP используют указанную allowlist; для резервной копии проекта с бинарными ресурсами сохраняйте полную папку. Source-репозиторий архитектуры не обязан включать runtime Node.js: его предоставляет портал/переносимый комплект. Git-субмодули, Git LFS и внешние пакеты требуют заранее материализованных локальных файлов; наличие ссылки на них не делает offline-снимок полным.

Источник: `seaf-mcp/engine.mjs` (`safe`, `model`, `propose`, `unchanged`) и `project-sources.mjs` (`inspect`, `connect`, `clone`); upstream поддерживает дополнительные сетевые адаптеры, отключённые в нашем offline-профиле.
