# Мастер подключения и диагностики

> Переносимый профиль: В переносимой версии подключайте папки через «Проекты». Git проверяется только для Git-источника; Docker — только для Docker runtime. Нативная проверка использует bundled Node.js. Пути . и порты ниже относятся к прежнему Docker-профилю. См. [инструкцию Windows](/entities/docs/blank?dh-doc-id=local.lsv.portable).

Feature: **28**. Capability: `connection-diagnostics`.

Откройте [рабочее пространство SEAF](/entities/docs/blank?dh-doc-id=local.lsv.workbench) или [страницу рабочего пространства](/entities/docs/blank?dh-doc-id=local.lsv.workbench). Выберите нужный проект; ниже пример для ShopFlow.

Раздел помогает определить, что мешает работе выбранного проекта. Он использует существующий реестр проектов и объясняет ошибки; автоматическая установка системных компонентов не выполняется.

## Как пользоваться

1. В верхнем списке **Проект** выберите нужную запись.
2. Откройте **Диагностика**. Проверьте карточку выбранного проекта: ID, доступ, манифест, портал, образ и корневой манифест runtime validation.
3. Нажмите **Проверить всё**. Посмотрите отдельные результаты: **Git**, **Модель и импорты**, **Docker**, **Конфигурация валидации**, **Образ SEAF**, **Портал и валидаторы**, **Редактор draw.io**, **Запись проекта**.
4. Исправьте причину, указанную в колонке **Что сделать**, и повторите **Проверить всё**.
5. Если сервис рабочего пространства перезапускался, нажмите **Подключиться заново** либо верхнюю кнопку **Обновить**.

## Пример ShopFlow

Для `shopflow` рабочая модель расположена в `seaf-docker/workspace/microservices-demo`, портал — `http://localhost:8080`. Если **Docker** вернул ошибку, запустите Docker Desktop в режиме Linux containers. Если **Git** показывает незавершённые изменения, сначала разберите их в репозитории.

Если портал временно недоступен, успешные результаты Git и импортов остаются в таблице. После восстановления повторите **Проверить всё**: успешный retry обновит соответствующий результат. Для справочного read-only проекта незавершённые изменения Git не дают права записи и не запрещают чтение доступных артефактов.

Если не работает встроенная схема, проверьте **Редактор draw.io**. Из каталога `./seaf-docker` локальный редактор запускается командой:

```powershell
docker compose up -d drawio
```

Затем повторите диагностику. Команда требует доступного Docker и добавленного compose-сервиса drawio.

## Подключение другого проекта

Мастер выбирает уже зарегистрированные проекты; создание записи пока выполняется в `./seaf-mcp/projects.json`. Проект для записи должен иметь собственный Git-репозиторий, manifest, validation workspace/образ и portal URL. Справочные скачанные проекты остаются только для чтения. Подробности — в [документации MCP](/entities/docs/blank?dh-doc-id=local.lsv.mcp).

## Ограничения

**Среда готова** означает успешность перечисленных проверок на момент запроса. Это не тест всех пользовательских сценариев. Если API полностью недоступен, таблица не загрузится: виден автономный режим, а подключение повторяется отдельно.

Проверки идут последовательно; сетевые запросы к порталу и редактору ограничены таймаутами. Мастер не меняет реестр, не запускает установку, не повышает права и не перезагружает Windows.

Карточка показывает разрешённую часть конфигурации: учётные данные, query-параметры и fragment URL портала исключаются. Сообщения о сбоях маскируют настроенные credentials и reload secret. Это не автоматическая очистка содержимого архитектурных файлов.

Ярлык проверяет готовность сервисов по IPv4 `127.0.0.1`, а открывает пользовательский портал по привычному localhost. Если загрузка остановилась, проверьте `seaf-docker/launcher.log` и `workbench-error.log`, затем повторите запуск.
