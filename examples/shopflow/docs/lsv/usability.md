# Удобство работы SEAF 2.2

Доработка объединяет поиск, реестры, паспорта, формы и проверяемое сохранение. Файлы проекта остаются источником архитектуры; личные представления и незавершённый ввод хранятся в браузере.

## Быстрый маршрут

1. В верхнем списке выберите проект. В строке контекста проверьте папку, тип источника, версию и доступ к записи.
2. Нажмите **Поиск** или **Ctrl+K**, введите `Delivery` и откройте паспорт Delivery Service.
3. Нажмите **Редактировать**, измените поле и выберите **Показать изменения**.
4. Изучите diff, выполните **Проверить в SEAF**, затем **Сохранить и обновить SEAF**.

## Возможности

| Доработка | Где пользоваться |
|---|---|
| Поиск объектов, документов и команд | **Поиск**, Ctrl+K |
| Полные реестры с фильтрами и представлениями | **Редактор** |
| Ошибки с переходом к объекту или полю | Результат проверки черновика |
| Паспорт системы | **Паспорт** в реестре или результат поиска |
| Контекст проекта и этап сохранения | Строка под верхней панелью |
| Автосохранение ввода, отмена и повтор | Форма объекта |
| Мастер создания системы | **Мастер создания** или **Моя работа → Создать систему** |
| Избранное, недавние объекты и ссылки | **Моя работа**, паспорт |
| Пошаговые сценарии | **Сценарии** |
| Понятные поля, помощь и расширенный JSON | Форма объекта |

## Пример ShopFlow

Найдите `demo.shop.delivery`, откройте паспорт и проверьте владельца `Logistics`. Посмотрите связи с заказами, добавьте объект в избранное и откройте его форму. Изменение описания сохраняется в браузере, но не в YAML до прохождения diff, проверки и явного сохранения.

## Ограничения

Личные настройки и ввод привязаны к браузеру, адресу локального сервиса и ID проекта. Они не переносятся в Git и не заменяют серверные черновики или бэкап. Переносимый запуск повторно использует прежние автоматически выбранные порты, если они свободны; при занятом порте выбирается другой. При смене порта/профиля браузера прежние настройки остаются у старого адреса: может потребоваться он или импорт ранее экспортированного черновика. Push на Git-сервер остаётся отдельным действием. Сценарии показывают описание из источников, а не фактическую трассировку работающей системы.
