# Оптимизация производительности SEAF

Дата: 2 ноября 2026 года. Исходная версия: `seaf-archtool-core` 2026.33.0,
коммит `c928383`. Изменения находятся в рабочей копии
`.\repositories\seaf-archtool-core`; публикация изменений ядра в upstream не выполнялась. Git-коммиты архитектурной модели ShopFlow учитываются отдельно.

> Исторический прогон: замеры выполнены 2 ноября 2026 года на исходной ShopFlow до добавления Delivery Service. Числа ниже не являются повторным замером текущей семисервисной модели.

## Что внедрено

1. **Кэш серверных данных в памяти:** ограниченный LRU на 1 000 записей,
   сохранение результатов `false`, `0`, `null`, `undefined`, пустой строки;
   одинаковые выполняющиеся запросы разделяют один Promise. После сброса кэша
   старый запрос не может заполнить новую версию устаревшими данными.
2. **Кэш SmartAnts:** до 32 схем и 8 MiB оценочного объёма строк UTF-16,
   ключ включает все входные данные схемы и ширину. Одновременные запросы
   объединяются. Отрисовка получает отдельную копию: выделение и изменение
   прозрачности элементов не портят сохранённую схему. localStorage не используется.
3. **JSON Schema:** один компилятор AJV и LRU до 100 скомпилированных схем.
   Ключ зависит от содержимого, поэтому изменение схемы с прежним `$id`
   создаёт новый валидатор. Внутренний реестр пользовательских схем AJV
   очищается после компиляции, чтобы не создавать второй неограниченный кэш.
4. **Файловый кэш:** асинхронные чтение, запись и перенос файлов;
   запись через временный файл с последующим rename; одинаковые обращения
   к файлу объединены. Исправлено восстановление пустой строки и null.
5. **Загрузка импортов:** очередь с пределом 16 одновременных загрузок
   (настраивается параметром конструктора Parser `importConcurrency`).
   URI отмечаются до завершения загрузки; повторные и циклические рёбра
   исключаются из дерева и регистрируются как ошибки.

## Методика

Обе версии работали на одном компьютере в Docker с Node 22.23.2.
Исходные файлы сохранены отдельным git worktree в `performance/baseline`.
Для HTTP-сравнения использовались порты 8081 и 8082, одинаковая модель ShopFlow,
одинаковый режим `memory`, одинаковые запросы. Финальный прогон выполнен
после завершения сборки. Нагрузочные сценарии запускались последовательно.

Микрозамеры: медиана 7 раундов. Обычные HTTP-ответы: 40 запросов после прогрева.
HTTP-валидация: 11 учитываемых запросов после первого; уникальный параметр
исключает попадание в кэш готового ответа. Перезагрузка модели: 7 повторений.
Это локальные инженерные измерения без статистического доказательства
ускорения на других компьютерах и моделях.

## Реальные вычисления и HTTP

| Сценарий | До, мс | После, мс | Интерпретация |
|---|---:|---:|---|
| HTTP-запрос со 100 вызовами JSON Schema | 247,27 | 5,16 | Примерно в 48 раз быстрее на этом сценарии |
| 100 проверок одинаковой схемы через JSONata, без HTTP | 238,25 | 1,51 | Устранена повторная компиляция |
| Повторный расчёт SmartAnts: 40 узлов, 39 связей | 2,85 | 0,27 | Примерно в 10 раз быстрее; 20 обращений к воркеру → 0 после прогрева |
| 30 одинаковых запросов с CPU-расчётом JSONata | 3,08 | 0,57 | Примерно в 5,4 раза быстрее; 30 вычислений → 1 |
| Получение меню, прогретый кэш | 1,99 | 1,91 | Существенное ускорение не установлено |
| Получение списка проблем, прогретый кэш | 1,86 | 1,78 | Существенное ускорение не установлено |
| Полная перезагрузка ShopFlow | 295,74 | 318,36 | Медиана хуже примерно на 8%; диапазоны повторений пересекаются |

SmartAnts измерен настоящей библиотекой из поставки, в Node worker, после
первого расчёта. Это время получения раскладки, а не загрузка всей страницы
и не отрисовка SVG в браузере. Проверен также запуск новой сборки интерфейса
и отображение схемы ShopFlow в браузере.

В `bench.mts` есть дополнительная проверка с искусственным воркером 5 мс.
Её результат не используется как доказательство ускорения настоящей схемы.
Ограничение импортов — мера устойчивости, а не универсальное ускорение.
Полная перезагрузка маленькой ShopFlow не стала быстрее.

## Повторение измерений

Из PowerShell в `.`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\performance\compare.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\performance\check.ps1
```

Для HTTP-сравнения сначала запустить стенды:

```powershell
docker compose -p seaf-performance -f performance/compose.yaml -f performance/optimized.compose.yaml up -d
node performance/http-validation.mjs
node performance/reload.mjs
node performance/http.mjs http://localhost:8081
node performance/http.mjs http://localhost:8082
```

Стенды запускать до готовности `/health`. После проверки:

```powershell
docker compose -p seaf-performance -f performance/compose.yaml -f performance/optimized.compose.yaml down
```

Сырые результаты: `before-*.log`, `after-*.log`, `*-matched-http.json`,
`http-validation.json`, `reload.json`, `jest-results.json`, `tests-*.log`.
Микрозамеры можно выполнить и из репозитория: инструкции в
`scripts/performance/README.md`.

## Установленная версия и откат

Основной портал использует локальный образ `seaf-local:2026.33.0-performance`
и кэш `memory`. Ранее кэш был выключен (`none`); в сравнении алгоритмов
обеим версиям был задан одинаковый режим memory. Папка с моделями и ярлык
запуска сохранены. После обновления открытого интерфейса используйте Ctrl+F5.

Для возврата исходной версии:

```powershell
Copy-Item -LiteralPath .\seaf-docker\compose.before-performance.yaml -Destination .\seaf-docker\compose.yaml
docker compose -f .\seaf-docker\compose.yaml up -d
```

Локальный образ содержит изменения рабочей копии. Автоматическое обновление
официального образа их не переносит; новая версия upstream потребует повторной
сборки и проверки.

## Изменённые участки ядра

Пути относительно `./repositories/seaf-archtool-core`:

| Изменение | Код |
|---|---|
| LRU и объединение одинаковых запросов | `src/global/helpers/bounded-cache.mjs`, `src/backend/storage/cache.mjs` |
| Кэш снимков SmartAnts | `src/frontend/helpers/smartantsCompute.ts`, `src/frontend/components/Schema/DHSchema/DHSchema.vue` |
| Повторное использование AJV | `src/global/jsonata/driver.mjs` |
| Асинхронный файловый кэш | `src/backend/storage/cache.mjs` |
| Ограничение загрузок и исключение повторных рёбер | `src/global/manifest/parser3/index.mjs` |

Самое заметное ускорение получено на повторной компиляции и вычислениях. Обычное получение меню и полная перезагрузка маленького проекта не показали универсального ускорения. Ограничение импортов и асинхронный I/O уменьшают давление на ресурсы и блокировки, но могут увеличивать время отдельной операции.
