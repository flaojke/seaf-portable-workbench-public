# Preview портала для ветки и черновика

> Переносимый профиль: Нативный preview запускает отдельный loopback-процесс с копией workspace. Поддерживаются Git refs, локальные ревизии, черновики и снимки. Историю папки обновляйте в «Сравнении». Docker-команды ниже описывают альтернативный профиль. См. [инструкцию Windows](/entities/docs/blank?dh-doc-id=local.lsv.portable).

Feature: **3**. Capability: `branch-preview`.

Откройте [рабочее пространство SEAF](/entities/docs/blank?dh-doc-id=local.lsv.workbench) или [страницу рабочего пространства](/entities/docs/blank?dh-doc-id=local.lsv.workbench). Выберите нужный проект; ниже пример для ShopFlow.

Preview запускает отдельный экземпляр портала с копией источников. Так можно осмотреть результат до публикации, сохраняя основной портал на localhost:8080.

## Preview черновика в интерфейсе

1. В **Объекты** подготовьте изменение или откройте сохранённый **Черновик**.
2. В **Предварительном просмотре** нажмите **Открыть preview**.
3. Дождитесь запуска Docker-контейнера. Откроется новая вкладка с отдельным локальным портом.
4. В результате операции сохранены id, URL, project, draftId/ref и срок expires.
5. Проверьте нужную страницу в preview. Для изменения live всё равно отдельно выполните **Проверить в SEAF** и **Сохранить в Git и обновить SEAF**.

## Пример ShopFlow

Подготовьте изменение description у `demo.shop.delivery` и откройте preview черновика. В отдельном портале найдите Delivery Service и убедитесь, что описание соответствует черновику. На основном портале прежнее состояние сохраняется до commit/reload.

Preview использует исходники черновика, но не создаёт за вас Git commit, merge или push. Сам факт доступности preview не заменяет полную validation.

## Preview Git-ветки

Откройте **Сравнение**, введите ветку или commit в поле **Целевая версия Git** и нажмите **Preview целевой версии**. Ref сначала разрешается в конкретный commit; рабочий HEAD не переключается. Внешний агент использует MCP-инструмент **create_preview** с project и ref.

Пример содержимого запроса локального API:

```json
{
  "action": "preview_create",
  "project": "shopflow",
  "ref": "HEAD"
}
```

API требует сессию и CSRF. Например, попросите агента: «Через MCP seaf создай preview проекта shopflow для ref HEAD и покажи отдельный URL и resolved commit».

## Ограничения и жизненный цикл

Preview требует Docker, runtime image и локально материализованных импортов. Порт доступен только на loopback. Открытые preview показаны в разделе **Сравнение**; кнопка **Остановить** освобождает контейнер. Срок жизни — 30 минут; action `preview_stop` также позволяет остановить его по id.

По умолчанию допускается до трёх активных preview; лимит задаётся `SEAF_PREVIEW_LIMIT`. При достижении лимита остановите ненужный экземпляр и повторите запрос. Ошибка сообщает этап подготовки, запуска или ожидания готовности; неготовый runtime не возвращается как доступный preview.

Общие внешние слои для Git-ref preview копируются из текущего validation workspace, а не из истории каждого репозитория.

В разделе **Снимки** кнопка **Preview** проверяет целостность сохранённого снимка, копирует его workspace и запускает указанный imageId с сохранёнными runtime manifest и environment. Это просмотр восстановленных источников без изменения live. Сам Docker-образ хранится отдельно и должен быть доступен локально.

Записи срока жизни сохраняются на сервере в `state/workbench/preview-records`. При перезапуске workbench таймеры восстанавливаются, а для просроченных записей запускается остановка. Пока сервис полностью выключен, его таймер не выполняется; остановка будет повторена после запуска при доступном Docker.

Загрузка произвольного внешнего ZIP и автоматическое перезаписывание live не выполняются. Список открытых preview в текущей вкладке не является полным инвентарём Docker-контейнеров.
