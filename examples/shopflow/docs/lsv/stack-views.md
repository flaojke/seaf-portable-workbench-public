# Stack views: архитектура из модели SEAF

Раздел Stack Diagram строит представления из текущей модели, не публикует её и не передаёт внешним AI-сервисам.

## Как использовать
1. Выберите проект и Stack Diagram.
2. Контекст показывает компоненты из выбранного contexts.components (точные ID или шаблоны с *).
3. Паспорт сервиса показывает прямые входящие и исходящие связи; в источниках доступны владелец, свойства и объявленные SEAF TA размещения. Нажатие на карточку или «Открыть объект» открывает редактор нужного раздела и ID.
4. Потоки данных показывают протокол и класс данных. Отсутствующие значения обозначены «Не указано». Анализ зон доверия и security policy review сюда не входят.
5. Технологический ландшафт фильтруется по точному ID технологии и объявленному статусу technologies. Наличие технологии в каталоге и отсутствие статуса различаются; статус компонента не выдаётся за статус технологии.
6. Размещение использует реальные связи seaf.ta.services.*.app_components → components, а также stand, network_connection, availabilityzone. Если связей нет, размещение не угадывается. Другие инфраструктурные метамодели и произвольные KADZO-связи не поддерживаются автоматически.
7. Сравнение принимает базовую и целевую Git/local revision либо ID актуального черновика. Добавленные, удалённые и изменённые узлы и связи выделены цветами. Общие узлы сохраняют позиции базовой версии. Изменённые параллельные связи сопоставляются по endpoints и порядку появления; отдельной постоянной link identity исходная модель не задаёт.

## Описание решения → проверяемое предложение
Локальный детерминированный parser понимает ограниченные русские и английские формулировки, по одной на строку:

    Сервис demo.new: Новый сервис
    demo.new передает данные в demo.shop.orders: Заказ; протокол=HTTPS; класс=business

Английские эквиваленты: Service ID: Title и FROM sends data to TO: Title; protocol=HTTPS; class=business. Также поддерживаются component ID | Title и link FROM -> TO | Title | protocol | classification.

demo.shop.orders должен существовать в выбранном проекте. Предварительный просмотр показывает точные operations и визуальный diff. Нераспознанный текст, повторные объекты и неизвестные endpoints отклоняются; отсутствующие факты не дополняются. «Сохранить проверенный черновик» лишь сохраняет draft. Затем откройте Черновики, просмотрите diff, сформируйте proposal, выполните validate и отдельно подтвердите apply. Изменение текста, проекта или исходной модели требует нового preview. Никакой автоматической записи предположений ИИ нет. Свободный произвольный текст и LLM не поддерживаются; размещение изменяйте редактором реальных SEAF TA объектов.

## Экспорт
После показа представления скачайте ZIP: diagram.html, diagram.svg, diagram.png, inventory.json, legend.json, NOTICE.txt, manifest.json. Manifest содержит дату UTC, revision, семантический SHA-256 модели, fingerprints обеих версий при сравнении и SHA-256 каждого файла. PNG строится локальным браузером. Это экспорт текущего ограниченного представления, не всех исходных файлов проекта. HTML статический, без внешних шрифтов, скриптов и иконок.

## Ограничения
До 200 узлов/600 связей в одном виде, до 400/1200 в сравнении; усечение обозначено предупреждениями. Собственная раскладка не заменяет полноценную автоматическую трассировку: на больших графах линии могут пересекаться. Для точных свойств используйте список объектов и связей. Импакт-анализ и пошаговый бизнес-сценарий не добавлены.

Рендерер реализован независимо, исходники и assets Stack Diagram не заимствованы. Страница подготовлена для меню «Доработки LSV»; публикация выполняется отдельно через MCP proposal lifecycle и не входила в эту локальную проверку.
