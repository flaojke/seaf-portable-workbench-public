# SEAF-Portable для Windows 10/11 x64

Версия MCP/Workbench: **2.2.0**. Новые возможности интерфейса и конструктор схем проходят отдельную приёмку OpenSpec `improve-seaf-usability`; номер версии сам по себе не подтверждает готовность окончательного ZIP. [Состав и критерии выпуска](../docs/release-2026-11-10.md).

## Запуск и перенос

1. Полностью распакуйте ZIP в папку с правом записи.
2. Запустите **Start.cmd** и дождитесь открытия браузера. **Stop.cmd** останавливает только свой экземпляр комплекта.
3. Откройте **Проекты**, выберите ShopFlow или Hello. В **Редакторе** доступны формы объектов и таблица информационных потоков.
4. Перед переносом остановите систему, затем скопируйте весь комплект вместе с `data`, если нужны настройки и история.

Node.js, Git, Java, PlantUML и draw.io включены в комплект. Docker, права администратора, установка ПО и интернет для локальных проектов не нужны. Сервисы используют свободные loopback-порты; адреса записываются в `data/run.json`. Повторный Start открывает уже работающий экземпляр.

`data/settings.json` позволяет задать `portalPort`, `workbenchPort` и `offlinePort`. Необязательный `activeProject` задаёт начальный пример при первом запуске; затем сохраняется проект, выбранный в интерфейсе. Проверка manifest обнаруживает изменение или неожиданный файл в неизменяемой части комплекта; пользовательские данные под `data` в неё не входят.

`app` и `runtime` содержат приложение и зависимости; `examples` — чистые примеры; `data/projects` — рабочие копии примеров; `data/projects.json` — подключения; `data/state` — черновики, ревизии, снимки и корзину. Внешние подключённые папки нужно перенести отдельно и переподключить при изменении пути. Не копируйте работающие процессы и не передавайте свою папку data посторонним без проверки её содержимого.

## Проекты и редактирование

В **Проектах** выберите папку Windows через диалог или введите путь, нажмите «Проверить папку», выберите манифест, затем «Подключить». Для Git доступны HTTPS/SSH URL и готовые клоны. URL не должен содержать пароль или токен.

«Выбрать» загружает модель в рабочее пространство, «Открыть» открывает портал выбранного проекта. «Сохранить ZIP» экспортирует поддерживаемые архитектурные файлы без Git metadata, бинарных assets и внешних импортов. «Новая версия» создаёт именованную локальную ревизию или Git-ветку без checkout и push. «Отключить» сохраняет файлы; «Удалить…» требует подтверждения ID и перемещает writable папку в локальную корзину.

Правки проходят **Редактор → Показать изменения → Проверить в SEAF → Сохранить и обновить SEAF**. Локальная папка получает ревизию без `.git`, Git-проект — локальный коммит. Push всегда выполняется отдельным явным действием. Ошибка обновления портала не отменяет сохранённую версию: повторите reload без повторной записи.

Hello показывает справочник владельцев и enum статусов. В ShopFlow можно изменить Delivery Service и его связь с заказами. Потоки редактируют настоящие `components.*.links`; остальные интеграционные сущности доступны как разделы модели. Дополнительные свойства сохраняются в JSON.

## Интерфейс и конструктор схем 2.2.0

Развитие рабочего пространства включает общий поиск Ctrl+K, реестры с сохранёнными фильтрами, паспорта объектов, понятные проверки, контекст сохранения, восстановление формы и отмену правок, мастер создания системы, избранное и недавние объекты, точные ссылки, прохождение сценариев и доступные формы. Инструкции каждой принятой возможности публикуются в «Доработки LSV» вместе с примером и ограничениями.

Конструктор позволяет собирать схемы сетевого, прикладного и компонентного уровней из объектов и связей. Сохранение схемы должно проходить **diff → проверка → сохранение в файлы проекта → обновление портала**; простое изменение предпросмотра не является записью проекта. Для сетевого уровня ручной элемент схемы не означает автоматического создания оборудования в неизвестной метамодели. Точная область поддерживаемых объектов и приёмка новой поставки фиксируются отдельно; старые результаты ZIP 2.1.0 их не заменяют.

## Интерактивная рабочая область 2.3

В **Схемы → Конструктор** выберите узел или линию. Вкладки **На схеме**, **В модели** и **Состав** разделяют оформление и настоящие архитектурные правки. Двойной щелчок открывает свойства; колесо меняет масштаб, фон/пробел с перетаскиванием перемещает вид, **Вписать** показывает схему целиком. Боковые панели и меню можно свернуть.

Для интеграции выберите **Что создать → Реальную интеграцию / поток модели**, конечные точки и поддерживаемое хранение связи. Изменения свойств, дочерних компонентов, явных контекстов и взаимодействий включаются в один черновик: **Предпросмотр и diff → Сохранить черновик → проверка → сохранить версию**. Неизвестные свойства сохраняются, Git push выполняется отдельно.

DocHub-состав использует `parent.child`; перенос существующего поддерева не входит в эту версию. Пользовательские конечные точки требуют объявленной схемы. Подробный пример Orders/API/Delivery и ограничения находятся в **Доработки LSV → 22. Интерактивный редактор схем**.

## Автономные схемы и ограничения

PlantUML, Mermaid и draw.io работают локально. Сетевые импорты и PlantUML include отключены. Внешние AI и Git-серверы требуют сети и собственной авторизации. Локальный draw.io поддерживает клиентское редактирование и сохранение XML; облачные интеграции, серверный PDF-export и MathJax не входят в профиль.

## Внешний MCP-агент

Запустите SEAF. Команда `runtime\node\node.exe portable\mcp-config.mjs` создаёт `data/mcp.config.json` с путями текущего комплекта для вашего MCP-клиента. После переноса сгенерируйте конфигурацию заново. `MCP.cmd` запускает stdio-сервер для клиента. Пароли и SSH-ключи пользователя в комплект не включены; закрытые репозитории используют его Git credentials/SSH-настройки.

## Сборка из исходного Git

Сборка выполняется на Windows x64. Для запуска сборщика нужен Node.js >=22.12 и интернет для первого получения закреплённых зависимостей:

```powershell
node portable/build.mjs --output dist/SEAF-Windows-x64
```

`--cache-root <папка>` позволяет использовать общий build-cache с проверенными runtime-архивами и production dependencies, сохраняя исходники из текущего checkout. `--offline-build` запрещает сетевое получение входов и запускает `npm ci --offline`; сборка завершится ошибкой, если нужных npm-пакетов нет в локальном кеше. `--skip-install` допустим только при уже установленных locked dependencies. Для выпуска используйте новую пустую output-папку; не перезаписывайте комплект с пользовательской `data`.

Ядро хранится в `vendor/seaf-archtool-core` с UPSTREAM provenance и исходными лицензиями. Входные runtime-архивы закреплены в inputs.json/offline-inputs.json и проверяются по SHA-256. Сборщик выпускает manifest и ZIP. Сборка не использует игнорируемые `repositories` или `seaf-docker/workspace`. Бинарная поставка, node_modules, data, кеши, персональные конфигурации и секреты не входят в исходный Git. Уведомления включённых компонентов находятся в `licenses` и runtime manifests.

Комплект — бинарная поставка форка **SEAF-Portable**, не исходный Git-репозиторий. Оригинал SEAF.ArchTool: https://gitverse.ru/seafteam/seaf-archtool-core. Целевой закрытый GitHub-репозиторий: https://github.com/flaojke/seaf-portable-workbench; факт публикации подтверждается отдельно. Ранее подготовленный адрес https://gitverse.ru/flaojke/seaf-portable-workbench сохраняется для справки; публикация туда в этот выпуск не входит. Происхождение и лицензии включены в корневые `UPSTREAM.md`, `NOTICE` и `LICENSE` комплекта.
